# Использование

Команды `ticket` на каждый день и формат файлов тикетов, которые он создаёт.

## Команды

Быстрый старт:

```bash
# создать тикет (статус open), печатает путь к файлу
ticket new "Поломка экспорта" -t BUG -p high -d "Падает на больших файлах" -w ivan

# длинные детали: из файла (@путь) или из stdin (-); содержимое переносится байт в байт
ticket new "Поломка экспорта" -d @details.md
ticket new "Поломка экспорта" -d -

# -P переопределяет проект (по умолчанию = basename родителя tickets/);
# предупреждение в stderr, если имя проекта встречается впервые
ticket new "Чужой проект" -P otherproj

# список тикетов: по умолчанию active (= open + wip)
ticket list
ticket list all        # включая done/closed
ticket list archive    # только архив
ticket list all -P otherproj   # фильтр по проекту (точное совпадение, регистр важен)

# показать тикет (ищет и в архиве)
ticket show 7

# сменить статус: open → wip → done / closed
ticket set 7 wip "взял в работу"
ticket set 7 done "починено, тесты зелёные"

# перенести закрытые тикеты (done/closed) в tickets/archive/
ticket archive         # все закрытые
ticket archive 7       # один указанный

# версия бинарника (dev, если собран без -ldflags)
ticket version
```

Предупреждения разбора печатаются в stderr; команда возвращает код выхода 0 и показывает успешно распарсенные тикеты.

Переменные окружения (`TICKETS_DIR`, `TICKET_WHO`, `TICKET_LANG`, `TICKET_LOCK_TIMEOUT`, `TICKET_LOG`) и глобальный флаг `-C`/`--tickets-dir`: [configuration.md](configuration.md).

### Ввод деталей (`-d`)

- Обычный текст — используется буквально.
- `@<файл>` — содержимое этого файла; содержимое переносится байт в байт (без обрезки, без конвертации переводов строк, без ограничения размера — больше 64 КиБ принимается).
- `@@имя` — файл с именем `@имя`: снимается ровно один маркер `@`, `@@` не является экранированием.
- `@` без пути — ошибка: путь после `@` обязателен.
- `-` — содержимое stdin.
- Пустой файл или пустой stdin — пустое значение `Details`; команда завершается успешно, а в созданном тикете показывается блок-формат `Details` (то же, что при `-d ""`).
- Отсутствующий файл или ошибка чтения stdin — ошибка: сообщение локализовано (ошибка файла называет путь), тикет не создаётся.

## Пример вывода list

Пример вывода `ticket list all` — колонка проекта появляется, когда проекты в выводе различаются:

```text
T-0001  tmp         open     BUG: Экспорт падает
T-0002  tmp         open     ENH: Broken export
T-0003  otherproj   open     BUG: Cross proj
```

С фильтром `-P` колонка проекта исчезает (проект один):

```text
T-0003  open     BUG: Cross proj
```

## Полная справка по командам

Полная справка по командам — текст `ticket help` (`TICKET_LANG=ru`), побайтово совпадает с встроенным шаблоном `internal/cli/templates/usage.ru.txt`. Бинарь печатает перед ним версионную строку (`ticket version <ver>`, `dev` если собран без `-ldflags`), которой в шаблоне нет:

```text
ticket — тикеты проекта (файлы T-NNNN-<status>.md в <проект>/tickets/).

  ticket init
      создать структуру тикетов в текущем каталоге: tickets/ и tickets/archive/ (идемпотентно)
  ticket new "<кратко>" [-t BUG|OPS|TD|ENH] [-p low|normal|high] [-d "<подробности>"] [-w кто] [-P <проект>]
      создать тикет (статус open), печатает путь к файлу;
      -P переопределяет проект (по умолчанию = basename родителя tickets/);
      предупреждение в stderr если проект встречается впервые
      -d принимает детали: обычный текст — буквально, @<файл> — содержимое файла, @@имя — файл с именем "@имя", - — stdin;
      @ без пути — ошибка: тикет не создаётся, сообщение локализовано;
      содержимое переносится байт в байт, пустой файл или stdin — пустое значение Details: в тикете показывается блок-формат Details (то же, что при -d ""); ограничения на размер нет;
      формат Details — нумерованный список, по одному пункту на строку: N. <что> — <файл:строка>; <решение>
  ticket list [active|open|wip|done|closed|archive|all] [-P <проект>] [--json]
      список тикетов; по умолчанию active (= open + wip);
      archive — закрытые тикеты, унесённые в архив;
      -P фильтрует по проекту (точное совпадение, регистр важен);
      колонка проекта отображается когда проекты в выводе различаются;
      --json выводит массив JSON (6 полей: number, status, type, priority, title, created); пусто = []
  ticket show <номер|имя-файла>
      показать тикет (ищет и в архиве)
  ticket set <номер> <статус> ["комментарий"]
      сменить статус (сам переименует файл и допишет строку в журнал тикета);
      повторный set в тот же статус с комментарием допишет журнал
      (статус и имя файла не меняются), без комментария — ошибка;
      перевод архивного тикета в open/wip возвращает его из архива в работу
  ticket archive [<номер>]
      перенести закрытые тикеты (done/closed) в archive/;
      без номера — все закрытые, с номером — один указанный

Глобальный флаг (перед командой, все команды кроме init):
  -C <путь>, --tickets-dir <путь>
      путь к самому каталогу тикетов (не к корню проекта); работает из любой текущей директории
  --verbose
      отладочный лог в stderr; TICKET_LOG=<путь> тоже включает лог и отправляет записи в этот файл (файл важнее флага);
      принимается только ДО имени команды; после help/version игнорируется; склеенная форма --verbose=x не распознаётся;
      stdout для записей лога никогда не используется

Поиск каталога тикетов (первое совпадение выигрывает): -C/--tickets-dir → $TICKETS_DIR → восходящий поиск tickets/ от текущего каталога.

Блокировка каталога: TICKET_LOCK_TIMEOUT задаёт, сколько ticket ждёт захват .lock, прежде чем вернуть ошибку; значение — Go-длительность с обязательной единицей (30s, 2m, 500ms); пустое или невалидное значение молча даёт дефолт; 0 или меньше — одна попытка без ожидания; действует на new, set и archive.

Статусы: open — новый; wip — в работе; done — исправлено; closed — отклонён/дубликат.
Типы: BUG — поломка; OPS — инцидент/обслуживание; TD — техдолг; ENH — улучшение.
Секреты (пароли, токены, ключи) в тикеты НЕ писать.
```

## Глобальные флаги

Распознаются два глобальных флага, и оба принимаются только ДО имени команды: `-C <dir>` / `--tickets-dir <dir>` (а также `--tickets-dir=<dir>` и склеенный `-C<dir>`) выбирает каталог тикетов для одного запуска, а `--verbose` включает отладочный лог.

`--verbose` пишет лог в stderr; если задан `TICKET_LOG` с путём, записи уходят в этот файл (файл важнее флага). stdout для записей лога никогда не используется. Токен, похожий на глобальный флаг, но стоящий ПОСЛЕ имени команды — это аргумент подкоманды, а не глобальный флаг: `ticket list --verbose` и `ticket new "T" -d x --verbose` — ошибки, а не тихие no-op. `--verbose` после `help`/`version` игнорируется, а склеенная форма `--verbose=x` не распознаётся.

```bash
ticket --verbose list                 # отладочный лог в stderr
ticket --verbose show 7 2>/dev/null   # лог всё равно в stderr, текст тикета остаётся в stdout
```

Формат записи, правила назначения, поведение при ошибках и полный список событий описаны в [configuration.md](configuration.md) — здесь они не дублируются.

## Формат файла тикета

- Имя файла: `T-NNNN-<status>.md`; номер выдаётся атомарно через OS-локи и не переиспользуется.
- Статус хранится в имени файла. Вручную файлы не переименовывать: смену статуса делает `ticket set` (сам переименует файл и допишет журнал тикета).
- Жизненный цикл: `open` (новый) → `wip` (в работе) → `done` (исправлено) / `closed` (отклонён/дубликат).
- Типы в заголовке: `BUG` — поломка; `OPS` — инцидент/обслуживание; `TD` — техдолг; `ENH` — улучшение.
- i18n: формат файла выбирается по `TICKET_LANG` в момент создания. Русская локаль даёт двуязычные метки (`## Summary (Кратко)`, `- Status (Статус): open`), английская — без перевода (`## Summary`, `- Status: open`). Файлы с чисто русскими заголовками (`## Кратко`, `- Статус:`) парсер не распознаёт: поля остаются пустыми, а ближайший `set` перезаписывает файл в текущем формате без них — такие файлы надо править вручную. Файлы формата pre-MD022 (текущий формат, но без пустой строки после заголовка) читаются и нормализуются при ближайшем `set`.
- `ticket new` без `-d` (или с пустым значением `Details`, например из пустого файла или stdin) вставляет в `Details` блок-формат — правило нумерованного списка: по одному пункту на строку, `N. <что> — <файл:строка>; <решение>`.
- Архив: `ticket archive` переносит закрытые тикеты в `tickets/archive/`; `list archive` смотрит архив; `show` и `set` работают с архивом, перевод архивного тикета в `open`/`wip` возвращает его в работу.
- Секреты (пароли, токены, ключи) в тикеты НЕ писать.

Пример тикета (`ticket new "Экспорт падает" -t BUG -p high -w ivan`, локаль RU):

```markdown
# T-0001 · BUG: Экспорт падает

- Status (Статус): open
- Priority (Приоритет): high
- Created (Создан): 2026-09-04 05:54 · by (кем): ivan
- Project (Проект): tmp

## Summary (Кратко)
Экспорт падает

## Details (Подробности)
<!-- Details = нумерованный список:
1. <что> — <файл:строка>; <решение>
-->

## User comments (Комментарии от пользователя)

## Comments (Комментарии)

## Journal (Журнал)
- 2026-09-04 05:54 — тикет создан (ivan).
```

## Секции

Секции: `Summary` — кратко; `Details` — подробности нумерованным списком, по одному пункту на строку: `N. <что> — <файл:строка>; <решение>` (файл:строка, логи, воспроизведение); `User comments` — пишет пользователь, агент читает перед работой над тикетом и туда не пишет; `Comments` — рабочие заметки агента; `Journal` — журнал, дописывается автоматически командами `new`/`set`.

Интеграция с агентами, кросс-проектная работа и архив в контексте: [scenarios.md](scenarios.md).
