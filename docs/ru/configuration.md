# Конфигурация

Переменные окружения, которые задают, где `ticket` хранит данные, кого записывает автором и на каком языке говорит.

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `TICKETS_DIR` | явный override каталога тикетов |
| `TICKET_WHO` | автор тикета; цепочка `TICKET_WHO → USER → USERNAME → agent` |
| `TICKET_LANG` | язык справки `ticket help` и файлов, создаваемых `ticket new`; цепочка `TICKET_LANG → LC_ALL → LANG`; известный префикс выбирает язык, неизвестный → EN, все пусты → RU (по умолчанию) |
| `TICKET_LOCK_TIMEOUT` | сколько `ticket` ждёт блокировку каталога тикетов (`.lock`), прежде чем сдаться с ошибкой вида `lock: ... still held by another process`; по умолчанию `5s` |
| `TICKET_LOG` | файл назначения отладочного лога; когда задан, лог включён и записи идут в этот файл вместо stderr |

Каждая цепочка вычисляется слева направо: побеждает первое непустое значение. `TICKET_WHO` откатывается к `USER`, затем к `USERNAME` (Windows), затем к литералу `agent`. `TICKET_LANG` откатывается к `LC_ALL`, затем к `LANG`. Его префикс (до первого `_` или `.`, без учёта регистра) выбирает известный язык; неизвестный префикс откатывается к английскому. Только когда все три пусты — используется русский (по умолчанию).

`TICKET_LOCK_TIMEOUT` перечитывается при каждом взятии блокировки, поэтому действует на каждый вызов независимо. Значение — длительность Go, единица обязательна: `30s`, `2m`, `500ms`, `1h`; единственное значение без единицы, которое принимает Go, — литерал `0`. Дефолт `5s` задан в коде (`internal/store/store_lock.go`, `defaultLockTimeout`) — второго места, где он задаётся, нет. Пустое или нераспарсиваемое значение (в том числе без единицы, например `5`) молча откатывается к этому дефолту, без предупреждения. Значение `<= 0` означает одну попытку взять блокировку, без ожидания. Переменная влияет только на мутирующие команды (`new`, `set`, `archive`); читающие (`list`, `show`) открывают каталог тикетов только на чтение и блокировку не берут.

Поднимайте его, если каталог тикетов лежит на медленном диске или на сетевой ФС, либо если параллельно работает много процессов `ticket` (CI, несколько агентов сразу) и блокировка удерживается дольше 5 s. Уменьшайте, если в загруженном каталоге лучше сразу получить ошибку, чем ждать.

## Отладочный лог (--verbose / TICKET_LOG)

`ticket` может вести структурированный отладочный лог собственной работы. По умолчанию лог выключен; им управляют один глобальный флаг и одна переменная окружения.

**Включение.** Лог включается, если глобальный флаг `--verbose` стоит ДО имени команды (`ticket --verbose list`), либо если `TICKET_LOG` непуста. Если ни того, ни другого нет — логирования нет вообще, и каждый байт вывода идентичен вызову без этой функции. Это относится к пяти логируемым командам (`new`, `list`, `show`, `set`, `archive`) — кроме их подкоманд `-h`/`--help`, которые печатают справку и не создают логгер; `init`, `help`, `version` и голый `ticket` вообще не создают логгер и полностью игнорируют `TICKET_LOG` — см. «Ошибка открытия» ниже.

**Назначение.** `TICKET_LOG` побеждает `--verbose`. С одним `--verbose` записи идут в stderr; с заданным `TICKET_LOG` они дописываются в этот файл: файл открывается на append, при отсутствии создаётся с правами «только владелец», существующий файл сохраняет свои текущие права, а родительские каталоги никогда не создаются. Ни одна запись не попадает в stdout — stdout остаётся чистым выводом команды. Оба назначения получают байт-в-байт одинаковые записи — обработчик один и тот же, различается только writer.

**Ошибка открытия.** Если лог-файл открыть нельзя, `ticket` печатает ОДНУ строку в stderr, называя путь дважды и оборачивая текст ошибки ОС, и выходит с кодом 1 ДО запуска команды. Для пяти логируемых команд (`new`, `list`, `show`, `set`, `archive`) отсутствие родительского каталога поэтому падает до dispatch: stdout пуст, код выхода 1, запасного варианта нет, ни один тикет не изменён. `init`, `help`, `version` и голый `ticket` вообще не создают логгер и полностью игнорируют `TICKET_LOG`. Пример (Linux; текст ошибки ОС на других платформах приведён только для иллюстрации):

```text
ticket: open log file /home/user/logs/ticket.log: open /home/user/logs/ticket.log: no such file or directory
```

Префикс `ticket: open log file ...:` — хардкоженный английский текст плюс сообщение об ошибке ОС, поэтому строка не зависит от локали: она выглядит одинаково при любом `TICKET_LANG`.

**Ошибка записи/закрытия.** Неудачная запись строки сообщается ОДНОЙ строкой в stderr после вывода команды — `ticket: log write: ...`; неудачное закрытие файла — ОДНОЙ строкой — `ticket: close log file <path>: ...`. Если НЕ УДАЛИСЬ и запись, и закрытие, обе ошибки объединяются, и обе строки выводятся вместе. Код выхода не меняется: после успешного открытия лог носит диагностический характер и фатальным не бывает.

**Формат записи.** Одна запись на строку: `ticket: <level>: <event> key=value ...`. Уровни — `debug`, `info`, `warn` и `error`; переключателя уровня и порога нет — пишется каждая запись, которую порождает код. Строки квотируются двойными кавычками через Go `strconv.Quote` (`command="new"`, пустая `path=""`); числа, булевы значения и длительности идут без кавычек (`code=0`, `timeout=5s`). Имя события и ключи остаются без кавычек, пока не содержат пробелов, `=`, кавычек, бэкслешей, управляющих символов или непечатаемых рун. Атрибуты выводятся в порядке порождения, без сортировки; групповые атрибуты рендерятся как `group.key`. Никакой отметки времени, вызывающего кода, файла или строки источника.

**Приватность.** Записи содержат только пути и операционные метаданные — никогда заголовок тикета, детали, комментарии, тело тикета или значения переменных окружения. CLI не контролирует расположение лог-файла: держать лог вне `tickets/` — ваша ответственность, потому что `tickets/` сканируется и разбирается инструментом.

**Канонический список событий.** Этот файл — единственное место, где события перечислены; [usage.md](usage.md) и скилл CLI лишь ссылаются на него.

| Событие | Уровень | Атрибуты | Когда порождается |
|---------|---------|----------|-------------------|
| `command.start` | info | `command` | каждая логируемая команда, до резолюции каталога тикетов |
| `command.done` | info | `command`, `code` | после возврата обработчика команды; НЕ выдаётся, если выполнение прервано до обработчика (резолюция каталога тикетов, открытие хранилища, проверка `who` журнала) |
| `dir.resolve` | debug | `source`, `dir` | каталог тикетов найден (`source` — `--tickets-dir`, `TICKETS_DIR` или `scan`) |
| `dir.resolve.fail` | error | `source` | резолюция каталога тикетов не удалась |
| `store.open` | error | `dir` | не удалось открыть store |
| `store.read.warning` | warn | `path`, `reason` | по одной записи на каждое предупреждение парсинга, показанное `new`/`list`/`set`/`archive` |
| `store.lock.acquired` | debug | `path` | блокировка каталога тикетов получена |
| `store.lock.released` | debug | `path` | блокировка освобождена |
| `store.lock.error` | error | `path`, `reason` | блокировку не удалось получить или освободить либо её файл подменили (`reason` — `timeout`, `error` или `swapped`) |
| `store.number.assigned` | info | `number` | `new` получил номер тикета |
| `store.number.retry` | debug | `attempt`, `max`, `number` | номер занят другим процессом, `new` повторил попытку |
| `store.set.append` | info | `number`, `status`, `path` | запись в журнал добавлена на месте (статус не изменился) |
| `store.set.commit` | info | `number`, `from`, `to`, `path` | смена статуса зафиксирована |
| `store.set.failure` | error | `number`, `to`, `stage` | смена статуса не удалась (`stage` — `collision`, `already`, `tmp`, `link` или `old`) |
| `store.set.append.failure` | error | `number`, `stage` | добавление записи в журнал на месте не удалось (`stage` — `tmp` или `rename`) |
| `store.archive.commit` | info | `number`, `status`, `path` | тикет перенесён в архив |
| `store.archive.failure` | error | `number`, `stage` | архивирование не удалось (`stage` — `already`, `not_closed`, `collision`, `tmp`, `link` или `old`) |

Байт-в-байт записи, выданные собранным бинарём (Linux):

```text
ticket: info: command.start command="list"
ticket: debug: dir.resolve source="scan" dir="/home/user/proj/tickets"
ticket: info: command.done command="list" code=0
```

Ошибочная запись выглядит так же, например провал открытия store:

```text
ticket: error: store.open dir="/home/user/proj/tickets"
```

**Флаг не на месте.** `--verbose` должен стоять ДО имени команды: разбор глобальных флагов останавливается на первом токене-не-флаге, поэтому после имени команды токен становится аргументом сабкоманды. Тексты этих ошибок флагов/аргументов следуют АКТИВНОЙ ЛОКАЛИ (по умолчанию — RU, когда локаль не задана); примеры ниже проверены с `TICKET_LANG=en` и приведены ТОЛЬКО на английском (EN-only):

| Вызов | Ошибка (только EN) | Код |
|-------|--------------------|-----|
| `ticket new "T" -d x --verbose` | `ticket: unknown argument: --verbose` | 1 |
| `ticket new --verbose "T"` | `ticket: title must not start with '-'` | 1 |
| `ticket list --verbose` | `ticket: unknown flag: --verbose` | 1 |

Склеенная форма `--verbose=x` не распознаётся и не срезается (`ticket list --verbose=x` падает с `ticket: unknown flag: --verbose=x`, код 1); `--verbose` после `help` или `version` игнорируется.

```bash
# записи в stderr
TICKET_LANG=en ticket --verbose list

# записи дописываются в файл (TICKET_LOG побеждает --verbose, так что флаг можно опустить)
TICKET_LOG=$HOME/ticket.log ticket list
```

## Приоритет флага

Глобальный флаг `-C` / `--tickets-dir` перекрывает `TICKETS_DIR` на один вызов. Полный порядок резолюции каталога тикетов — в [installation.md](installation.md).

## Примеры

```bash
# один вызов против песочницы
ticket -C /tmp/sandbox/tickets list

# то же через окружение
TICKETS_DIR=/tmp/sandbox/tickets ticket list

# англоязычная справка
TICKET_LANG=en ticket help

# записать конкретного автора
TICKET_WHO=ivan ticket new "Экспорт падает" -t BUG -p high

# ждать блокировку каталога тикетов до 30 секунд (только мутирующие команды)
TICKET_LOCK_TIMEOUT=30s ticket new "Экспорт падает" -t BUG -p high
```

Сборка бинаря и прогон тестов: [development.md](development.md).
