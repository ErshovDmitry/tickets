# Установка

Как установить бинарь `ticket`, как он находит каталог тикетов и как подготовить проект.

## Установка бинаря

Положите бинарник в `PATH`:

- Linux / macOS: `~/bin/ticket`
- Windows: `%USERPROFILE%\bin\ticket.exe`

Бинарь сам находит каталог тикетов из любой текущей директории, поэтому копия в каждом проекте не нужна. Это один статический бинарник, собранный с `CGO_ENABLED=0`, с нулём runtime-зависимостей.

Сборка из исходников — [development.md](development.md).

## Резолюция каталога тикетов

Порядок резолюции (первое совпадение выигрывает):

1. `-C <путь>` / `--tickets-dir <путь>` — override на один вызов, путь к самому каталогу тикетов;
2. `$TICKETS_DIR`;
3. восходящий поиск от текущей директории каталога с именем `tickets` (как у git).

Переменные окружения описаны в [configuration.md](configuration.md).

## Замечание о миграции

Проекты, созданные старыми версиями, хранят бинарь или симлинк в `tickets/bin/` — при вызове изнутри дерева проекта они продолжают работать, потому что восходящий поиск по-прежнему находит `tickets/`.

Что больше не работает: вызов этого бинаря по абсолютному пути из посторонней директории в расчёте на его расположение. Используйте `-C <каталог-тикетов>` или `TICKETS_DIR`. Устаревшую копию `tickets/bin/` можно удалить в удобный момент.

## Быстрый старт

Из корня проекта:

```bash
ticket init
```

Это создаст `tickets/` и `tickets/archive/`. Команда идемпотентна. Бинарь она **НЕ** устанавливает — держите один `ticket` в `PATH`.

## Один бинарь — много проектов

Один бинарь в `PATH` обслуживает все проекты: соберите его один раз в `~/bin/ticket`, затем в каждом проекте выполните `ticket init` — он создаст структуру тикетов.

```bash
VER=$(git describe --tags --always 2>/dev/null | sed 's/^v//'); VER=${VER:-dev}
CGO_ENABLED=0 go build -ldflags "-X ticket/internal/cli.version=$VER" -o ~/bin/ticket ./cmd/ticket
cd <проект>
ticket init
```

Детали сборки и цели кросс-компиляции: [development.md](development.md).

## Git: коммитить или игнорировать

Если проект под git — решите, коммитить `tickets/` вместе с проектом или добавить его в `.gitignore`. Оба варианта рабочие: коммит делает тикеты частью истории проекта и позволяет смотреть их в `git diff`; игнор оставляет их локальными для машины.
