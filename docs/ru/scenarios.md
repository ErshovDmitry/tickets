# Сценарии использования

Типовые сценарии работы с `ticket`: интеграция с ИИ-агентами, кросс-проектные тикеты, архив, секреты и скилл для агентов. Команды и формат файла тикета — в [usage.md](usage.md), переменные окружения — в [configuration.md](configuration.md).

## Интеграция с агентами

Вставьте блок ниже в `AGENTS.md` проекта, использующего `tickets/` (если файла нет в корне проекта — создайте; пути относительные — от корня проекта; бинарник сам найдёт каталог тикетов независимо от текущей директории):

```markdown
## Тикеты (`tickets/`)

- НА СТАРТЕ сессии: `ticket list` — если есть открытые тикеты, кратко напомни о них пользователю при первом же ответе.
- Нашёл во время работы проблему, ошибку или что-то подозрительное — СРАЗУ создай тикет: `ticket new "<кратко>" -t BUG|OPS|TD|ENH -p low|normal|high -d "<подробности>"`. НЕ молчи, даже если удалось обойти/починить по месту. В подробностях указывай файл:строка.
- Смена статуса — только через `ticket set <номер> <статус> "<комментарий>"` (бинарник сам переименует файл и допишет журнал тикета); вручную файлы тикетов не переименовывать.
- Перед работой над тикетом прочти его секцию «User comments (Комментарии от пользователя)» — замечания оставляет пользователь; агент туда не пишет. Свободные рабочие заметки агента — в «Comments (Комментарии)».
- Тесты/smoke-прогоны `ticket` — ТОЛЬКО в песочнице (временный каталог через `$TICKETS_DIR`), НИКОГДА в боевом `tickets/`.
- Закрытых тикетов (`done`/`closed`) стало много — перенеси их в архив: `ticket archive`. Архивные не теряются: `ticket list archive`, `show`/`set` работают и с ними, reopen возвращает тикет в работу.
- В тикеты НЕ писать секреты (пароли, токены, ключи).
```

## Кросс-проект

По умолчанию проект тикета — basename родительского каталога `tickets/`. Флаг `-P` переопределяет проект на один вызов:

```bash
ticket new "Чужой проект" -P otherproj
```

Предупреждение в stderr печатается, если имя проекта встречается впервые — защита от опечатки. Список фильтруется по проекту (точное совпадение, регистр важен):

```bash
ticket list all -P otherproj
```

Колонка проекта в выводе `ticket list` появляется, только когда проекты в выводе различаются; с фильтром `-P` она исчезает (проект один) — примеры в [usage.md](usage.md).

## Работа с архивом

Закрытые тикеты (`done`/`closed`) не удаляются — `ticket archive` переносит их в `tickets/archive/`: без номера — все закрытые, с номером — один указанный (`ticket archive 7`). Архивные тикеты не теряются: `ticket list archive` смотрит архив; `show` и `set` работают и с архивом, а перевод архивного тикета в `open`/`wip` возвращает его из архива в работу.

## Секреты

Секреты (пароли, токены, ключи) в тикеты НЕ писать.

## Скилл для агентов

В репозитории поставляется скилл для агентов в `skills/ticket-cli/` (`SKILL.md` + `reference.md`) — обучает ИИ-агентов рабочему процессу с тикетами: команды, жизненный цикл и подводные камни. Установка — скопировать каталог в `~/.agents/skills/ticket-cli/`.
