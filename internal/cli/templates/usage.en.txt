ticket — project tickets (T-NNNN-<status>.md files in <project>/tickets/).

  ticket init
      create the tickets structure: tickets/, tickets/archive/ and tickets/deleted/ (idempotent); honors -C/--tickets-dir and $TICKETS_DIR (default: <current directory>/tickets)
  ticket new "<brief>" [-t BUG|OPS|TD|ENH] [-p low|normal|high] [-d "<details>"] [-w who] [-P <project>]
      create a ticket (status open), prints the file path;
      -P overrides the project (default = basename of tickets/ parent);
      warning to stderr if the project is seen for the first time
      -d takes the details: plain text — literally, @<file> — file content, @@name — file named "@name", - — stdin;
      @ without a path is an error: no ticket is created, the message is localized;
      the content is copied byte for byte, an empty file or stdin gives an empty Details value — the ticket then shows the Details format block (the same as -d ""); there is no size limit;
      Details format — a numbered list, one item per line: N. <what> — <file:line>; <fix>
  ticket list [active|open|wip|done|closed|archive|deleted|all] [-P <project>] [--type BUG|OPS|TD|ENH] [--priority low|normal|high] [--json]
      list tickets; default active (= open + wip);
      archive — closed tickets moved into the archive;
      deleted — soft-deleted tickets in tickets/deleted/; every other mode (active/open/wip/done/closed/archive/all) hides them and all still covers the main directory only;
      -P filters by project (exact match, case-sensitive);
      --type/--priority filter by type and priority (exact match, case-sensitive), combined with the status and -P filters by AND;
      an invalid --type/--priority value is an error (exit 1)
      project column shown when output tickets have differing projects;
      --json outputs a JSON array (6 fields: number, status, type, priority, title, created); empty = []
  ticket show <number|filename> [--section <name>] [--json]
      show a ticket (the archive and deleted/ are searched too); a duplicate number is exit 2 with every conflicting path
      --section prints only the section body without the header (empty or missing section: exit 0, empty stdout; unknown name: exit 1)
      --json prints one JSON document: number, status, type, priority, project, title, summary, created, who, details, user_comments, comments, journal[], unknown, unknown_encoding, warnings[]; status comes from the file name
      the modes are mutually exclusive; diagnostics go to stderr only; extra positional args: warning (exit 0) in plain, error (exit 1) in --section/--json
  ticket set <number> <status> ["comment"]
      change the status (renames the file itself and appends a line to the ticket journal);
      re-setting the same status with a comment appends a journal entry
      (status and file name unchanged), without a comment it is an error;
      the comment may be given as ONE argument: - — stdin, @<file> — file content, @@name — file named "@name";
      a bare @ as the ONE comment argument (no path) is an error (exit 1), a missing file and a failed stdin read are errors too — the ticket name, its bytes and the journal stay unchanged;
      the content is copied byte for byte, and exactly one trailing LF or CRLF is stripped; any other CR or LF — a second trailing LF, a lone trailing CR, an embedded line break — is refused (exit 1), nothing is written;
      two or more comment arguments are joined with a space and used literally — no file and no stdin is read;
      trade-off: a lone "-" or "@..." argument is never a literal comment, and two arguments are not a byte-exact escape (the join inserts a space);
      "-" reads stdin to the end of the input; on a terminal it waits for EOF (Ctrl-D)
      moving an archived ticket back to open/wip restores it from the archive into work;
      set never assigns deleted: naming it, or a ticket whose file lives in deleted/, is refused — exit 1, the file is unchanged
  ticket edit <number> [--title "<brief>"] [--type BUG|OPS|TD|ENH] [--priority low|normal|high] [--project <project>]
      edit the title/type/priority/project of a ticket in place (status and file name never change);
      an archived ticket is edited inside the archive/ without a reopen, --project only changes the metadata;
      only separate "--flag value" pairs: "--flag=value" and short flags are refused; a repeat keeps the last value;
      an explicitly unchanged value refuses the whole edit (exit 1, nothing is written); success is silent (exit 0);
      a ticket whose file lives in deleted/ is refused (exit 1, nothing is written)
  ticket comment <number> [-] [--file <path>] [--json] [--schema]
      append a text block to the Comments section (never a replacement); the payload source is exactly one of - (stdin) or --file <path>;
      no source or both sources is a usage error (exit 1) and the terminal is never read; --file is read byte for byte, an empty file is read as an empty payload;
      --json treats the payload as strict JSON {"text":"<payload>"} (single field): unknown fields are exit 1 with the field list/format/example, invalid JSON or trailing garbage are exit 1 with position/format/example, never a plain-text fallback;
      --schema prints the JSON Schema to stdout (exit 0, no lookup, no write) and cannot be combined with a source;
      only separate "--flag value" pairs after the positional number; a payload line that is a markdown heading (1-6 '#' then whitespace or end of line) is refused (exit 1) with its line number;
      an empty payload is refused (exit 1); success is silent (exit 0), parse warnings go to stderr; a deleted/ ticket is refused, an ambiguous number is exit 2 with every conflicting path
  ticket section set <number> <section> [-] [--file <path>] [--json]
      replace the body of an editable section; <section> is a canonical CLI token (a protected or unknown name is refused, exit 1, listing the editable names);
      the payload source is exactly one of - (stdin) or --file <path>; no source or both is a usage error (exit 1), the terminal is never read;
      --file is read byte for byte (an empty file clears the section); --json treats the payload as strict JSON {"text":"<payload>"} (single field), unknown fields or invalid JSON are exit 1, never a plain-text fallback;
      an empty payload clears the section (an empty summary renders as the title); a payload markdown-heading line is refused (exit 1) with its line number;
      only separate "--flag value" pairs after the positionals; success is silent (exit 0), parse warnings go to stderr;
      a deleted/ ticket is refused (exit 1), an ambiguous number is exit 2 with every conflicting path
  ticket archive [<number>]
      move closed tickets (done/closed) into archive/;
      without a number — all closed ones, with a number — only the given one;
      deleted tickets are ignored: never moved into the archive and never restored from it
  ticket recover <number> <new-file> [--yes]
      recover a ticket after an interrupted status change that left two files for one number;
      <new-file> is the basename to keep (for example T-0001-done.md), never a path;
      without --yes it prints the kept and the deleted file and asks yes/no;
      without --yes and without a terminal it refuses and changes nothing;
      only the stale old file is removed, the kept file is never rewritten;
      a repeat after a successful recovery, and a single file already named <new-file>, are a conservative no-op success;
      recover only checks that the wanted file is present: it cannot prove that it is the previously saved file and not a lone stale one,
      so exit 0 means "the wanted name is already on disk", not "a recovery happened"
      exit 2 when the number is not cleanly recoverable (three or more files, diverging contents, equal statuses in the file names);
      keeping the stale file, naming a file outside the pair or a single file with another name is exit 1 and changes nothing;
      a crash pair that includes deleted/ is recovered the same way — keeping the deleted file is allowed, keeping the stale source stays exit 1
  ticket delete <number|filename> [--yes] [--force]
      soft-delete a ticket into deleted/ (body, metadata and journal are preserved; one transition-to-deleted journal line is appended);
      <number|filename> is one ref: a number or an exact base name (for example T-0001-open.md), never a path;
      without --force only an open ticket in the main directory is deletable; --force also covers the other main statuses and archive;
      without --yes it prints the candidate path and asks yes/no; without --yes and without a terminal it refuses and changes nothing;
      --yes skips the prompt but never the guard; a duplicate number or an identical base name in several directories is exit 2 with every conflicting path;
      an exact base name picks one file out of a duplicate number; already deleted, a target collision or a not-found ref is exit 1 and changes nothing;
      a repeat after a successful delete is exit 1 (already deleted), never a no-op success; success prints the deleted file's path
  ticket normalize [-P <project>] [--dry-run]
      one-shot: bring legacy ticket files to the canonical markdown layout;
      only files whose bytes differ from the canonical form are rewritten: the name and status stay the same,
      the journal gains no line (there is no migration journal entry);
      -P limits the run to one project (exact match, case-sensitive);
      --dry-run prints the paths that would be rewritten and writes nothing;
      files the command will not fix are skipped with a warning (old "- Status:" labels, incomplete metadata);
      deleted tickets are rewritten in place too (walk order: main, then archive, then deleted)
  ticket update-check
      newer release on GitHub? (explicit; never automatic); per-user cache (24 h), 1 h backoff; offline-safe: failure never blocks other commands

Global flag (before the command, every command):
  -C <path>, --tickets-dir <path>
      path to the tickets directory itself (not the project root); works from any current directory
  --verbose
      debug log to stderr; TICKET_LOG=<path> also enables logging and sends the records to that file (the file wins over the flag);
      accepted only BEFORE the command name; after help/version it is ignored; the glued form --verbose=x is not recognised;
      stdout is never used for log records; init ignores --verbose (no logger is built for init)

Tickets dir discovery (first match wins): -C/--tickets-dir → $TICKETS_DIR → upward scan for tickets/ from the current directory. Exception: init uses <cwd>/tickets without an upward scan.

Lock timeout: TICKET_LOCK_TIMEOUT sets how long the .lock may remain without holder progress before ticket returns an error (while the holder keeps working, the wait is extended up to 12× the configured value); the value is a Go duration with a mandatory unit (30s, 2m, 500ms); an empty or invalid value silently falls back to the default; 0 or less means a single attempt with no wait; it applies to new, set, edit and archive.

Exit codes: 0 — success; 1 — error (bad arguments, ticket not found, collision, input or store error, failed update check); 2 — ambiguous ticket number (commands show, set, edit, archive, new, recover, delete, comment, section): one number belongs to several files — the number and the conflicting files are printed to stderr. The list command prints the same warning for duplicates but exits with code 0; 3 — update available (command update-check). Duplicate numbers inside `tickets/deleted/` follow the same rules: `list` (any mode) warns and exits 0, `show` exits 2 with every conflicting path, and `set`/`edit` refuse a deleted ticket with exit 1.

Statuses: open — new; wip — in progress; done — fixed; closed — rejected/duplicate; deleted — soft-deleted (terminal, read-only).
Types: BUG — breakage; OPS — incident/maintenance; TD — tech debt; ENH — enhancement.
Secrets (passwords, tokens, keys) must NOT be written into tickets.
