# ticket

[English](README.md) | **Русский**

Кроссплатформенная (Windows / Linux / macOS) CLI-система тикетов на Go.

## Что это

- Тикеты — обычные Markdown-файлы `T-NNNN-<status>.md` в каталоге `tickets/` проекта; единственный источник правды — файлы: читаются человеком без инструментов (`cat`, редактор, `git diff`), база данных не нужна.
- Один статический бинарник `ticket` (`ticket.exe` на Windows), собирается с `CGO_ENABLED=0`, ноль runtime-зависимостей.
- Кроссплатформенный аналог bash-версии [init-tickets.md](https://gitlab.com/ai-dmitry/promts/-/blob/main/init-tickets.md).

## Быстрый старт

Из корня проекта:

```bash
ticket init                                             # создать tickets/ (идемпотентно)
ticket new "Поломка экспорта" -t BUG -p high -d "Падает на больших файлах"
ticket list                                             # активные тикеты (open + wip)
ticket show 7                                           # показать тикет (ищет и в архиве)
ticket set 7 done "починено, тесты зелёные"             # сменить статус, файл переименуется сам
ticket recover 7 T-0007-done.md                        # разрулить пару после прерывания (неоднозначный номер, код 2)
```

## Коды выхода

- `0` — успех.
- `1` — ошибка: неверные аргументы, тикет не найден, конфликт, ошибка ввода или хранилища.
- `2` — неоднозначный номер тикета: номер принадлежит нескольким файлам тикетов; номер и конфликтующие файлы печатаются в stderr (пути абсолютные).

`ticket recover` использует те же коды: `0` — ещё и консервативный no-op (повтор после успешного восстановления либо единственный файл, уже названный `<файл-новый>`): код 0 значит, что нужное имя файла есть на диске, и никогда не доказывает, что восстановление произошло; `1` — неверный вызов, отказ подтверждения, тикет не найден, ошибка ввода-вывода (включая сканирование архива), выбор старого файла (keep old) и имя, не являющееся парой после прерывания; `2` — номер не восстановим автоматически: больше двух файлов, расходящееся содержимое или одинаковые статусы. Диагностика неоднозначности печатает оба конфликтующих пути абсолютными, а `<файл-новый>` для `recover` — всегда базовое имя файла без каталога.
