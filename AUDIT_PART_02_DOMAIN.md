## Риски и предложения

- 🟡 `Parse` намеренно останавливает обработку журнала на первой нераспознанной строке и переносит хвост в `Unknown`. Это безопасно для сохранения данных, но последующие корректные journal-записи после ручной строки не будут распознаны как записи. Стоит явно закрепить это поведение в документации/тесте (или перейти к построчному tolerant parsing, если нужна индексация).
- 🟡 `Filename` не валидирует номер/статус сам по себе; контракт защищён вызывающими слоями. Можно добавить defensive API или тесты на отрицательные номера/неизвестные статусы.
- 🔵 Инициализация i18n использует `panic` при повреждении embedded ресурсов. Для неизменяемых ресурсов это приемлемо; при дальнейшем вынесении языков наружу потребуется runtime-ошибка.

- 🔴 `internal/cli/cmd_new.go: title validation` допускает перевод строки в заголовке. При `new "line one\nline two"` H1 становится многострочным, а после `set` парсер сохраняет только `line one`; данные теряются. Рекомендация: отклонять `\r`/`\n` в title (и, желательно, в однострочных meta-полях) отдельным тестом.
